## 테마 하위 메뉴 클릭 오류 수정

상위 ContextMenuStrip의 Bounds만 검사하던 전역 마우스 처리로 인해, 옆에 열린 하위 메뉴 클릭이 바깥 클릭으로 처리되어 메뉴가 닫혔다. 열린 하위 메뉴를 재귀적으로 포함하도록 수정했다.

FOREST-02를 보강하여 실제 WinForms 상위/하위 팝업을 열고, 상위 메뉴 바깥이면서 하위 메뉴 항목 안인 좌표를 전역 필터와 같은 처리 메서드에 전달했다. 테마 4개 모두 클릭 전에 메뉴가 닫히지 않고 선택이 반영됨을 검사했다. 상위 메뉴 내부 클릭은 유지하고, 전체 메뉴 바깥 클릭은 닫히는 것도 검증했다. OS 마우스 입력 주입 검사는 아니다. 이전 PerformClick만 호출한 검사는 이 바깥 클릭 처리 경로를 통과하지 않아 오류를 발견하지 못했다.

## 테마 변경 시 수정 표시 및 상단 테마선

수정 전 네이티브 검사에서 CRLF 파일은 편집에 들어가지 않고 테마만 변경해도 Dirty=true가 되는 현상을 재현했다. `_loaded`에는 CRLF가, RichTextBox.Text에는 LF가 있어 잘못 비교되었다. 로드 후 편집기 텍스트를 기준으로 저장하도록 수정했다.

수정 후 CRLF/LF/CR 파일 각각에서 4개 테마 전환 시 내용·파일 바이트·미수정 상태를 확인했다. 실제 미저장 편집 내용은 테마 변경 후에도 내용과 `*`를 유지하고, 원래 내용으로 되돌리면 `*`가 사라지는지 검사했다. 상단 테마선의 색상·2px 높이·탭 아래 위치·전체 너비가 검색/강조 바·편집/분할·리사이즈 후에도 유지되는지 실제 WinForms 레이아웃으로 확인했다.

검사 전용 WebView 사용자 데이터 폴더를 `obj/verification/wv2`로 분리해 실행 중 앱의 프로필과 충돌하지 않도록 했다.
