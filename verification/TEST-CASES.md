| CARET-01 | 편집 중 두 VIEW에서 이전 line/clickLine/heading 위치 메시지 전달 | 편집 커서, 선택 범위, 포커스 및 스크롤 위치 유지 |
| CARET-02 | 긴 문서 편집 중 오른쪽 VIEW를 스크롤하고 스크립트로 제목 click() 호출 | 편집기 위치와 선택 범위 유지 |
| CARET-03 | 편집 중 미리보기를 갱신하고, 220ms 후 이미지 높이가 12px에서 1800px로 증가하도록 로드한 뒤 입력 | 왼쪽 위치/선택 범위/포커스를 보존하고 원래 의도한 위치에 입력 |
| CARET-04 | 연속 입력 중 매번 VIEW 갱신·레이아웃 변화·스크롤을 발생시키고 창 크기 변경 | 입력이 다른 위치에 섞이지 않으며 커서와 선택 범위 유지 |

편집기 또는 VIEW를 마우스로 클릭하면 양쪽에 기존 삼각형과 함께 대응 위치의 동일한 테마색 2px 언더라인이 표시된다. 편집기와 VIEW의 선택 위치는 모두 화면 상단 35% 지점으로 맞춘다. 선은 즉시 표시되고 유지 없이 0.5초 동안 페이드아웃된다. 방향키·문자 입력만으로는 언더라인을 새로 표시하지 않는다.

실행: `& .\verification\Run-Checks.ps1 -CursorOnly -EditorOnly`

기존 현재 줄 삼각형·편집기→VIEW 동기화·분할·Word·테마·홈 샘플 검사: `& .\verification\Run-Checks.ps1 -CursorOnly`

홈 링크 검사에는 왼쪽의 두 샘플 파일 링크와 오른쪽의 `md 파일 연결프로그램 등록`·GitHub 링크 표시, 링크 간 겹치지 않는 다단 배치, 현재 테마 색상·글꼴 적용 여부를 포함한다. 샘플 링크는 실행 파일과 같은 폴더에 파일을 생성하며 기존 파일은 보존한다. 연결 등록 링크는 HKCU 레지스트리에 `.md`/`.markdown` 연결을 기록하고 Windows 기본 앱 안내 다이얼로그를 표시한다.

| HOME-04 | 홈 화면의 `md 파일 연결프로그램 등록` 링크 확인 | Windows 연결 등록 안내 링크의 표시·배치와 현재 테마 스타일이 정상 |
| HOME-05 | 연결 등록 안내 팝업을 블루스카이·포레스트 그린에서 열기 | `기본 앱 설정 열기` 버튼 배경이 각 테마의 포인트 색상으로 표시 |
| HOME-07 | 홈 화면의 `diagram-sample.md 열기` 링크 확인 | 실행 파일과 같은 폴더에 내장 다이어그램 샘플이 추출되고 새 탭으로 열림 |

## 사용자의 명시적 VIEW 클릭

자동 갱신/이미지 로딩/스크롤의 역방향 동기화는 금지하되, 실제 사용자 클릭만 편집 위치 이동으로 처리한다.

| ID | 절차 | 기대 결과 |
|---|---|---|
| CLICK-01 | 긴 자동 줄바꿈 문단 뒤의 제목을 오른쪽 VIEW에서 직접 클릭하고 입력 | 해당 원문 논리 줄로 커서·포커스 이동 후 정확한 위치에 입력 |
| CLICK-02 | 빈 줄을 보완해 렌더링한 표의 셀 클릭 | 원래 Markdown 표 행으로 이동 |
| CLICK-03 | VIEW 버튼 클릭 및 편집 모드를 종료한 상태에서 본문 클릭 | 버튼 동작은 실행되지만 편집 커서 이동 없음, VIEW 모드도 유지 |

CLICK 검사는 WebView2의 브라우저 입력 이벤트를 발생시켜 `isTrusted`가 참인 실제 클릭 경로를 검증한다. 단순 DOM `click()` 호출은 커서 이동을 발생시키지 않는다.
